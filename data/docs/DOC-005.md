# Decision update: publication-scoped unsubscribe policy

Owner: Neri Vale, Messaging Infrastructure. This record supersedes D-07 in DOC-004 for unsubscribe events created after the new policy is enabled. It does not reverse the subscriber-export postponement in DOC-003.

## Updated decision
D-12: We replaced workspace-wide unsubscribe suppression for new unsubscribe events with publication-scoped suppression because pilot feedback showed that recipients recognized separate publications and wanted to leave one without leaving all of them. CHAT-004 documents the feedback; TCK-005 records the implementation update.

A publication is a named sending stream with its own recipient-facing identity. It is not an audience or a saved segment. Each campaign must select exactly one publication before scheduling. Membership in overlapping audiences does not broaden the unsubscribe scope.

## Safety and migration
D-13: We preserved existing workspace-wide unsubscribe records because narrowing an earlier opt-out without new permission could restart messages recipients expected to stop. The migration does not infer publication consent from opens, clicks, or audience membership.

Hard bounces remain workspace-wide. The preference page offers both “leave this publication” and “leave all publications,” with the latter creating a workspace-wide suppression. The send worker checks both scopes before delivery.

## Release conditions
The policy is approved, but production rollout is gated on passing the two-publication regression suite and reviewing preference-page copy. Approval of this record is not evidence of a completed deployment.

The onboarding-email recipient expansion in CHAT-003 is a different decision affecting Pulse's own setup messages. Neither that expansion nor this unsubscribe update unlocks subscriber CSV export, which remains postponed at the end of this corpus. Campaign report PDFs remain a separate aggregate-reporting feature.
