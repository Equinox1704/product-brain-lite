# Sync scheduling update: guarded administrator refresh

Owner: Sora Pell. This record updates recurring inbound synchronization from DOC-007. It does not change the manual CSV import contract in DOC-006 or authorize any subscriber download.

## Evidence and updated scope
The connector prototype now serializes work using a per-source lease and tracks the accepted source revision. Administrators in fictional pilot workspaces reported needing a refresh after correcting source records, without waiting for the next nightly run. These are prototype observations, not evidence of production deployment.

## Decisions
D-29: We updated D-17 to allow administrator-triggered refresh alongside the nightly batch because the per-source lease now prevents overlapping runs and a deduplication key collapses repeated refresh requests. Nightly processing remains the default; this is a scheduling expansion rather than continuous synchronization.

## Preserved guarantees
D-18 remains unchanged: upstream subscription flags cannot clear Pulse suppressions. A manual refresh uses the same revision checks, field permissions, and aggregate status display as a scheduled run. If a run already holds the lease, the interface reports that work is in progress rather than starting a second worker.

## Acceptance and release gate
TCK-007's later comments adopt this update, while TCK-014 covers lease-expiry recovery. The refresh control remains gated on concurrency and retry tests. The policy approval in this document is not a deployment confirmation.

A failed refresh must preserve the last successful state and show a retryable error. It must not empty an audience, create a rejection-file download, or reset an unsubscribe. Subscriber CSV export remains postponed under D-25.
