# Deliverability decision: shared suppression list baseline

Owner: Neri Vale, Messaging Infrastructure. This record defines the initial scope of suppression caused by a recipient unsubscribe. It does not define whether an administrator receives Pulse onboarding emails.

## Initial policy
D-07: We chose workspace-wide unsubscribe suppression because the initial sender identity model provides only one recognizable brand per workspace. A recipient who unsubscribes should not receive another campaign merely because the sender selected a different audience.

A matching normalized address is suppressed across audiences within that workspace. An unsubscribe in one workspace does not change another workspace. Hard-bounce handling is a separate mechanism and remains workspace-wide under this proposal.

## Implementation contract
The send worker checks suppression immediately before delivery, not only when assembling a campaign audience. The preferences page explains the affected workspace. Audit records retain the event type, timestamp, and initiating campaign identifier, without copying the entire message body.

TCK-005 implements the initial unsubscribe scope. It must include a test in which a recipient belongs to two audiences and unsubscribes through a campaign sent to only one of them.

## Limitations and review
The policy may be too broad for customers operating distinct publications under one workspace. For this initial version, the interface must explicitly describe the workspace-wide effect; it must not claim that an unsubscribe is limited to one audience.

A later policy change requires a dated replacement record and an explicit rule for existing suppressions. Customer feedback can motivate that review but cannot silently alter the worker contract. CHAT-004 will be used to collect publication-specific feedback after the initial implementation is tested.
