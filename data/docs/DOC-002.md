# Activation spec: in-app onboarding checklist

Owner: Elian Marr, Design. Scope: the persistent setup panel inside Pulse, not the onboarding email sequence described in DOC-001.

## Experience
The panel contains three tasks: verify a sending domain, import an audience, and create a draft campaign. Each task links to the relevant screen. Creating a draft completes the third task even if the campaign is never sent; the panel represents setup progress rather than the activation metric used by the lifecycle-email project.

## Decisions
D-03: We made the checklist dismissible because experienced administrators should not have a permanent setup panel after migrating from another tool. Dismissing it is a per-user preference and does not change workspace task state.

D-04: We derive completion from persisted workspace events because a clicked help link does not prove that a setup action succeeded. Failed imports leave the import task incomplete.

## Permissions and boundaries
Administrators can perform all three tasks. Collaborators see the same workspace progress but receive a permission explanation instead of an unavailable action. Reading a guide, opening an onboarding email, or receiving an email delivery notification never completes a task.

Checklist state must survive refreshes and support two administrators working simultaneously. A removed verified domain reopens the verification task. Existing campaign drafts count when the panel is introduced.

## Validation
TCK-002 covers dismissal persistence and task-state tests. CHAT-001 records confusion between email suppression and checklist completion. Usability sessions will ask participants to explain why a task is complete; success means they cite the underlying action rather than a message they received. No additional lifecycle emails are authorized by this specification.
