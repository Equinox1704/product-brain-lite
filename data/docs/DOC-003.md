# Roadmap decision: subscriber CSV export postponed

Owner: Sora Pell, Engineering. This record concerns downloading subscriber records from a workspace. It does not cover campaign performance reports, chart images, or inbound CSV imports.

## Decision and reason
D-05: We postponed subscriber CSV export from the spring milestone because the existing read path does not reliably apply field-level access restrictions to custom attributes. Shipping a download before enforcing those restrictions could expose fields a collaborator cannot view in the interface.

The feature is postponed, not cancelled. There is no committed release date. TCK-003 remains blocked until an authorization design and test matrix are reviewed. Support must not promise a release based on the existence of the ticket.

## Scope of a future implementation
A subscriber export would include email address, subscription state, and authorized custom fields for a selected audience. Suppression reasons need separate review. Downloads would require an administrator, an expiring link, and an audit event. These are proposed requirements, not delivered capabilities.

D-06: We kept campaign report PDF work in the current milestone because its aggregate metrics do not depend on the restricted subscriber-field read path. A PDF report must not include recipient-level rows or subscriber addresses.

## Communication and review
The roadmap should use the label “subscriber CSV export: postponed, authorization dependency.” Avoid the unqualified phrase “exports postponed,” which could incorrectly imply that aggregate campaign reporting is also blocked.

CHAT-002 captures a fictional customer's request for campaign results, a different need from downloading the audience itself. Review D-05 after the authorization prototype passes negative-permission tests. A working prototype alone does not authorize a public launch.
