# Bounce classification and retry boundaries

Owner: Neri Vale. Scope: delivery failures reported by the sending transport. A bounce is not a recipient unsubscribe, and classifying a transport response must not create publication consent.

## Classification contract
Persist an event identifier, campaign identifier, response category, and receipt timestamp. A definitive permanent delivery failure is a hard bounce. A temporary failure is a soft bounce and can remain eligible for bounded retries. Unknown responses remain unclassified pending review instead of being treated as consent changes.

## Decisions
D-19: We keep hard-bounce suppression workspace-wide because repeatedly attempting a permanently unreachable address through another audience or publication wastes delivery capacity without creating a valid destination. This preserves the hard-bounce boundary described in DOC-004 and later retained in DOC-005.

D-20: We limited temporary-failure retries to three attempts within twenty-four hours because unbounded retries would compete with new campaigns and make delivery status difficult to explain. A hard bounce stops further retries immediately.

## Acceptance and exclusions
Duplicate callbacks must not increment retry counts twice. A soft bounce does not mark a subscriber unsubscribed. The activity screen must distinguish a retryable delivery failure from a deliberate preference change.

TCK-008 covers worker behavior and the callback deduplication tests. Preference-page wording and recipient opt-out choices belong to DOC-009. Publication-scoped unsubscribe work must not narrow hard-bounce suppression. This specification approves no deployment date and does not imply that TCK-005's later unsubscribe migration has shipped.
