# Campaign report scheduling without automatic distribution

Owner: Fenna Orr. Scope: a proposed reminder to review aggregate campaign results. The proposal does not establish that the PDF attachment in TCK-004 has shipped and does not extend reporting to subscriber-level data.

## Product outline
An administrator chooses a campaign and a review date. Pulse creates an in-app reminder linking to the existing report view. The reminder contains a campaign label and timestamp but no subscriber addresses, custom attributes, or recipient-level click history. Aggregate metrics remain subject to report permissions when the user opens the view.

## Decisions
D-27: We postponed automatically emailing campaign report attachments because report access can change between scheduling and delivery, and the first scheduler cannot revalidate attachment permissions at send time. The initial proposal is an in-app reminder only.

D-28: We chose an explicit reporting timestamp because campaign totals may continue to change after a review reminder is created. A reminder must not imply that its original preview is a permanently final result.

## Acceptance and limitations
Removing report access prevents the reminder from opening protected results. Deleting a campaign cancels pending reminders. The scheduler deduplicates repeated save requests and shows the currently configured review date.

TCK-013 records the excluded emailed-attachment shortcut. This work does not replace TCK-004's PDF QA and cannot unblock TCK-003's subscriber export. A future automatic-distribution proposal must explain authorization revalidation before it can supersede D-27. No outbound attachment release is approved here.
