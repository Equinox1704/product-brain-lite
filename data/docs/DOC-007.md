# Subscriber sync connector baseline and conflict policy

Owner: Sora Pell. Scope: recurring inbound subscriber updates from a fictional customer-managed source. This is not the one-time audience CSV import in DOC-006 and does not provide outbound subscriber export.

## Product contract
An administrator configures one source identifier and a target audience. A sync run records its start time, completion state, and aggregate counts. Missing source records do not delete Pulse subscribers automatically. Suppression checks remain authoritative regardless of source values.

## Decisions
D-17: We chose nightly batch synchronization rather than an on-demand refresh because the first worker design lacks a safe per-source concurrency guard and overlapping runs could apply updates out of order. This is an initial scheduling policy, not a permanent product limitation.

D-18: We made Pulse suppression state authoritative because an upstream subscribed flag must not silently undo a recipient's unsubscribe. Source updates may change permitted profile fields but cannot clear an opt-out.

## Conflict handling
The connector records a source revision for every accepted update. An older revision must not overwrite a newer one. Source failures leave the last successful state visible and do not mark the audience empty. Administrators see a summary rather than a downloadable subscriber-level reconciliation file.

TCK-007 implements this baseline. DOC-006 remains the contract for manual uploads; its partial-acceptance preview does not establish synchronization scheduling. Any later addition of manual refresh requires a replacement decision explaining serialization and duplicate-request handling. Neither this connector nor its status screen resolves the export authorization dependency in DOC-003.
